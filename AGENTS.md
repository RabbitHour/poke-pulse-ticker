# Project rules
- Preserve the React routes and existing Cloud/provider integrations; the refresh is additive rather than a platform migration.
- Archive source releases and forecast outcomes in the existing public file ledger; repeated checks never manufacture price history.
- Use shared forecast eligibility/direction rules for generation and display so pending, stale and late results cannot inflate accuracy.
- Treat set forecasts as fixed launch-basket indexes, adding observations only with complete current constituent coverage.
- Keep exact catalog product/variant identifiers in internal links; card-level fallback links must not masquerade as catalog records.- Use the catalog asset pointer only as a bootstrap fallback; current daily catalog files take precedence, and Vite proxies the asset path same-origin to preserve CSP.
